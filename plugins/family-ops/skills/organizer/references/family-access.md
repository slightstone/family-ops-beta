# Family access to the manual organizer

Only a valid customer-owned Kids installation can offer this feature. Read the current role first. The board's Settings → Family access is the actual owner flow; there is no family-invitation MCP tool. It shares all people, parent-entered items, manual activities and completion with an adult member. Optional source-derived contexts, source bodies, connector settings and owner administration remain private. There are no child accounts or per-child shared scopes in this release.

An owner confirms the intended adult name/email and exact role: Viewer by default; Editor only after explicit choice. Changing recipient/role requires refreshed confirmation. At most five adults including owner, five pending invitations and seven-day expiry. Prepare only after the owner confirms that scope. The app produces the actual one-time invitation link; never invent a link, print its raw code in technical logs, claim it was sent or send it externally without exact separate approval. Lost create response cannot re-display the code: use the app's saved invitation/cancel/replacement recovery; do not blindly recreate.

The recipient must authenticate to the exact private Site with the intended email, preview scope/role and explicitly accept. Preview does not grant membership. Wrong account, expired/canceled invite, revoked grant or disabled sharing is unavailable, never a new-board setup. The private Site's outer viewer permission is separate, customer-owned consent/effect; a Family access invitation does not grant it. Use only the host's actual supported private viewer grant with exact recipient approval, or explain the unavailable gate. Never make the Site public to make an invitation work.

Editors use current workspace/revision and grant proof for manual commands; viewers read only. Owner revoke/cancel and member Leave are explicit current-authority actions in the app. Revocation clears protected content; retain only an actual readable unsaved draft. Leave acknowledges leaving; exact authenticated actor/request/grant-bound retry can return only that confirmation. It cannot reopen the board. Owner installation and sources remain unchanged.

## Optional protected host setup

Manual organization works without sharing configuration. If Family access is unavailable, the owner may separately approve enabling FAMILY_OPS_KIDS_SHARING=enabled on their exact own Site and securely provisioning FAMILY_OPS_INVITE_KEY_V1 through the host's protected secret control. Runtime requires a64-lowercase-hex invitation key; do not generate, retrieve, request, transmit or log its value through the assistant, model arguments, chat, files, screenshots or package. Only a separately qualified customer-controlled secure entry path is appropriate. If unavailable, leave sharing unavailable and continue the manual board. Do not reuse another secret or change the legacy planner sharing flag.

Verify exact owner Site/configuration and preserve all unrelated keys/identity. Follow installed Sites guidance for protected human entry and saved metadata/readback, never assume typing saved a secret. Key loss may block new invitations/acceptance but must not be used to prevent authenticated cancel/revoke/leave. No cloud/native/customer install or external invitation delivery is established by local fictional acceptance.
